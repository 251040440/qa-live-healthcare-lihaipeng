## 架构概述

QA Server 采用微服务架构设计，将系统拆分为多个独立的服务单元，每个服务专注于特定的业务领域。

### 架构原则

1. **单一职责**: 每个微服务专注于单一业务领域
2. **独立部署**: 服务可独立构建、测试、部署
3. **松耦合**: 服务间通过 API 通信，降低耦合度
4. **高可用**: 支持服务注册、发现、容错
5. **可扩展**: 支持水平扩展应对业务增长

### 服务清单

| 服务 | 端口 | 职责 | 状态 |
|------|------|------|------|
| qa-service-user | 8080 | 用户管理、医生/患者管理 | 开发中 |
| qa-service-question | 8081 | 问题管理、问答处理 | 开发中 |
| qa-service-statistic | 待定 | 数据统计、报表分析 | 规划中 |

## 微服务设计

### 用户服务 (qa-service-user)

**职责范围**:
- 用户注册、登录、认证
- 医生信息管理
- 患者信息管理
- 权限控制

**核心实体**:
- User（用户）
- Doctor（医生）
- Patient（患者）

**API 设计**:
```
POST   /api/users/login        # 用户登录
POST   /api/users/register     # 用户注册
GET    /api/doctors            # 获取医生列表
GET    /api/doctors/{id}       # 获取医生详情
GET    /api/patients/{id}      # 获取患者信息
```

### 问题服务 (qa-service-question)

**职责范围**:
- 问题提交和管理
- 问题回答处理
- 问题状态跟踪
- 问答历史查询

**核心实体**:
- Question（问题）

**API 设计**:
```
GET    /api/questions          # 获取问题列表
POST   /api/questions          # 提交问题
GET    /api/questions/{id}     # 获取问题详情
PUT    /api/questions/{id}/answer  # 回答问题
```

### 统计服务 (qa-service-statistic) - 规划中

**职责范围**:
- 业务数据统计
- 报表生成
- 数据分析
- 可视化展示

## 数据架构

### 数据存储策略

```
┌──────────────────────────────────────────────────┐
│                   应用层                          │
├──────────────────────────────────────────────────┤
│  用户服务数据库   │   问题服务数据库   │   统计服务数据库  │
│   (user_db)      │   (question_db)    │   (statistic_db)  │
└──────────────────────────────────────────────────┘
```

### 数据一致性

- 每个服务拥有独立数据库
- 避免跨服务数据库访问
- 通过 API 进行数据交互
- 使用事件机制保证最终一致性

## 安全架构

### 认证流程（规划中）

```
┌──────────┐     ┌──────────┐     ┌──────────┐
│  Client  │────▶│  Auth    │────▶│  User    │
│          │     │ Service  │     │ Service  │
└──────────┘     └──────────┘     └──────────┘
     │                │
     │    JWT Token   │
     │◀───────────────┘
     │
     │  Request + Token
     ▼
┌──────────┐
│Resource  │
│ Service  │
└──────────┘
```

### 安全措施

| 层级 | 措施 |
|------|------|
| 传输层 | HTTPS 加密 |
| 认证层 | JWT Token |
| 授权层 | RBAC 权限控制 |
| 数据层 | 敏感数据加密 |

### CORS 配置

当前配置允许开发环境跨域访问：

```java
@Configuration
public class CorsConfig implements WebMvcConfigurer {
    @Override
    public void addCorsMappings(CorsRegistry registry) {
        registry.addMapping("/**")
                .allowedOriginPatterns("*")
                .allowedMethods("GET", "POST", "PUT", "DELETE", "OPTIONS")
                .allowedHeaders("*")
                .allowCredentials(true)
                .maxAge(3600);
    }
}
```

## 扩展规划

### 短期规划

1. **数据库集成**
   - 添加 MySQL/PostgreSQL 支持
   - 集成 Spring Data JPA
   - 实现数据持久化

2. **认证授权**
   - 集成 Spring Security
   - 实现 JWT 认证
   - 添加 RBAC 权限控制

3. **API 文档**
   - 集成 SpringDoc/Swagger
   - 自动生成 API 文档

### 中期规划

1. **微服务治理**
   - 引入 Spring Cloud
   - 服务注册发现（Nacos/Eureka）
   - 配置中心
   - 服务网关（Gateway）

2. **消息队列**
   - 引入 RabbitMQ/Kafka
   - 实现异步通信
   - 事件驱动架构

3. **缓存机制**
   - 集成 Redis
   - 会话管理
   - 数据缓存

### 长期规划

1. **容器化部署**
   - Kubernetes 编排
   - Helm Charts
   - CI/CD 流水线

2. **可观测性**
   - 分布式追踪（Sleuth/Zipkin）
   - 日志聚合（ELK）
   - 监控告警（Prometheus/Grafana）

3. **高可用设计**
   - 服务熔断（Resilience4j）
   - 负载均衡
   - 限流降级
